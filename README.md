# Codex Audit

审查 Codex 为什么理解偏了、无依据附和，或说改好了却没有改善。它帮助 Agent 定位原话与后续纠正，对照实际产物，撤回失效的工作依据，再继续下一项真实动作。你可以只要审查，也可以让出现问题的原对话完成修复并继续任务。

这是基于 r5 的 **v0.1.0-rc.1 公开试用版**。无需 Agent Check、More Than Yes、私人记忆或专用聊天插件。已观察到证据定位进入原对话的实际制作；完整恢复、稳定优于原工作方式和用户整体满意仍未证明，具体结果见 [验证记录](VALIDATION.md)。

## 开始使用

[下载试用包](https://github.com/Ww-Cooooo/codex-audit/releases/download/v0.1.0-rc.1/codex-audit-v0.1.0-rc.1.zip)，解压后保留完整 `codex-audit` 文件夹。最短的试用方式是在你选择的 Codex 对话中发送下面的话，把路径和案例换成实际内容：

```text
读取 <codex-audit 文件夹的完整路径>/SKILL.md，并按它审查我下面提供的案例。
这次先只审查，不联系其他对话。
案例：<当时的要求、不满意的结果，以及必要的片段或产物位置>
```

Agent 需要具备读取该文件夹的权限。首次结果应说明具体偏差、证据、仍不确定的原因和下一步验证办法；材料不足时会说明盲区。直接读取文件使用不等于已经安装或验证了自动触发。

审查界面、视频或声音的效果，还取决于宿主能否实际呈现相应内容。只有代码、静态截图或生成的录屏时，能查到部分问题，不能据此保证已经评价动态手感或声音；本包不会替宿主增加这些感知能力。

需要在各项目发现这个 Skill 时，可以将整个文件夹复制到用户级 `~/.agents/skills/codex-audit`；Windows 对应 `%USERPROFILE%\.agents\skills\codex-audit`。已有同名目录时先保留并核对旧副本。随后在新建的 Codex 对话中确认可发现它，再用 `$codex-audit` 调用。已打开的对话仍可按上面的完整路径明确读取；安装不会清除旧历史，也不保证所有对话自动改善。这里提供安装方法，交付包本身没有执行安装。

也可以在 Codex 中请内置的 `$skill-installer` 从 `https://github.com/Ww-Cooooo/codex-audit` 安装本版：仓库内路径为 `.`，名称为 `codex-audit`，版本为 `v0.1.0-rc.1`。这是独立 Skill 包，不需要插件服务。需要当前任务直接纠正并继续时，可明确要求：

```text
使用 $codex-audit 审查当前任务的具体偏差，在已有授权范围内纠正并继续下一步实际工作。
只处理当前对话，不联系其他对话；不把报告或续接文件当作修复完成。
```

只使用审查流程无需 Python。需要可选原文定位、续接生成、元数据采集或运行附带测试时，使用 Python 3.11 或更新版本，无第三方库依赖。

## 它怎样审查

- 先确定有效要求和实际缺口，追查用户决定是否被 Agent 建议、举例或旧摘要替换。
- 检查判断改变前后的证据。新偏好应当被采纳；没有新证据时，不把猜测改口说成事实。
- 检查一次纠正是否进入随后关键决定与产物。修改规则和口头承诺本身不算效果改善。
- 按证据选择补材料、修工具、改方法或修具体规则，并说明验证办法。

只审查时到结论和建议为止。你明确要求修复后，原任务负责人在原对话执行范围内的改动、继续工作并检查结果。若审查发生在别处，默认交付可带回原任务的改法；明确授权协调指定对话后，可交接证据、固定方法版本并回收实际结果。它不会自行联系未授权的聊天。

修复会同时检查仍有效的旧要求，避免一个问题解决后另一个目标丢失；也会区分过去的相对偏好、允许实施和现在是否满意。审查者自己的比较条件和通过标准也要追到来源，避免把临时样本或方便检查的数字变成用户未提出的限制。易混情形见 [判断实例](references/judgment-cases.md)。你同时要求改进审查方法时，才会将本轮仍依赖作者提示的环节补进 Skill，并单独验证。

它可以用于当前问题，也可比较你指定的多个案例。聊天长度、缓存占用、Skill 数量和模型价格都只是可能的调查线索，不能单独作为原因。普通小改和已定位的单个故障不用先运行整套审查。

## 原文定位与续接

新增工具能在明确指定的消息导出或文本中查询关键词、取相邻原话、标明来源位置和未读范围。它不依赖聊天插件，不扫描全部对话，也不替 Agent 决定哪项偏好有效。

修复时，原负责人可把旧依据、新依据和下一项实际动作连同真实引文生成续接材料，再在原对话执行。生成文件仍是待执行；只有后续动作和产物能说明采用。工具输出会包含原文和本机路径，留在获准案例范围内，不随公共包分享。

用法与支持格式见 [原文定位工具](references/evidence-access.md#原文定位工具)。普通短任务直接使用当前原话和已有任务记录，不必先生成一套文件。

## 可选的环境清点

附带脚本只读取你明确指定的配置、指令文件、Skill 根目录或 JSONL 记录，输出有限元数据。它不扫描全部聊天、不查找登录凭据、不联网，也不会执行被读取的内容。配置只导出限定字段。它只在指定位置创建新报告，拒绝覆盖已有文件。

读取记录时，脚本只提取元数据，不输出对话原文，也不作诊断。元数据不足时，Agent 仍需在你的授权范围内核对原始要求和产物。报告不含绝对路径和对话正文，但会包含技能名称和用于定位的相对目录名，分享前仍需复核。Codex 对材料的分析遵循你使用的 Codex 服务的数据处理方式，不能因为脚本不联网就认为整个分析都在本机完成。

参数、限制和示例见 [证据采集说明](references/evidence-access.md)。没有 Python 或可用日志时，仍可用你提供的片段完成有范围的审查。

## 怎样验证效果

用真实案例的要求和产物检查理解、判断和后续采用情况，不按“反对了几次”或报告篇幅打分。只要效果不明显、出现额外返工或缺少关键证据，就保留这个结果。

本包包含元数据采集及原文定位、续接生成的合成测试。在包目录运行：

```text
python -B -m unittest discover -s tests -v
```

这些测试验证读取范围、输出处理和异常情况，不能证明 Agent 判断更好。当前案例范围、协助条件和未验证项见 [验证记录](VALIDATION.md)。真实案例与修复按用户提供的材料和授权推进，不会自行干预其他对话。

具体方法见 [效果验证办法](references/evaluation.md) 和 [修复与实际验证](references/repair-and-verification.md)。

## 试用后反馈

问题可以带回维护对话，或由你决定是否在 [GitHub Issues](https://github.com/Ww-Cooooo/codex-audit/issues) 提交。保留正在使用的版本、当时想完成什么、实际偏到哪里，以及纠正后下一步究竟做了什么；提供最少必要的原话或产物即可。区分安装/读取问题、工具报错和已经读取却判断错误，方便修改对应位置。

让使用中的 Agent 整理反馈不会自动联系其他对话、提交 Issue 或更新公共包。完整聊天、日志和本机路径先留在自己的环境；公开反馈前由你选择可分享的片段。不要为了反馈而重新制造一次任务或复制全部上下文。

Codex 的 Skill 结构与用户级目录依据 [官方 Skill 文档](https://learn.chatgpt.com/docs/build-skills)；宿主的发现与加载行为仍需在使用者环境中确认。
