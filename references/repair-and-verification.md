# 纠正与续接

用于已授权修复；仅审查无需实施。目标是让原任务的下一步改变，而非再写一篇解释。

## 把取证结果变成当前工作依据

选择正在影响下一步、且已有证据可纠正的一项依据。直接更新原任务记录中的相关部分；短任务可在当前回合简短说明，不必另建文档。保留原件和足够比较的差异。

一份可用的纠正应能回答：以前依据什么行动，现在哪项原文或产物使它失效或需要收窄，下一步因此怎样改变，还要保留哪些要求。这里的“依据”也可以是数据处理、验收方式或工具状态，不限于口头理解。

例如，原任务已用“没有溢出”认定打印清单合格，用户原话却要求打印后直接找到负责人。下一步是恢复可打印的负责人并实际生成打印结果；改写报告中“合格”两字并没有完成纠正。这不要求把所有旧要求永久冻结；若用户明确改成只在屏幕使用，修复依据应随之改变。

需要获准交接、压缩后续接或较长操作时，用 [定位工具的 resume](evidence-access.md#生成有来源的续接依据) 生成一份材料：工具从指定来源重新取出所选原文，写入当前任务、旧依据、新依据、下一动作、保留项和观察办法。执行者负责这些判断；工具不认定原因或核准修改。已有可靠任务记录时也可直接更新它，不并行维护多份相同状态。

## 接着做，而不是停在材料

当前 Agent 在原对话修复时，采用纠正继续已获授权的下一步。外部审查已获协调许可时，将完整固定包和正常任务材料交给原负责人，不替它写出预期诊断要求照单认领。回收实际结果，亲自核对动作和产物；不把“收到”“准备改”或自述完成当成采用。

资料不足先补会改变行动的资料。方法已经执行却不足时，指出现有产物中的具体关系与目标缺口，完成有理由的可逆改法或能区分路线的比较。若主要缺口依赖缺失的专业能力或感知证据，补相应条件或交付可实际审阅的关键产物；不反复以另一处微修报进度，也不把核心问题放进“待验收”后称修复完成。

没有新任务时不制造任务凑持续性。一次续接能说明当次采用，不能承诺长期不再偏离。

## 核验是否真的改变了动作

围绕被纠正的主张检查实际结果。先看核验动作是否真的触发相关情况，再看响应：例如筛选检查要实际改变返回对象，数值更新检查要确认目标读数确实变化。输入没发生相应改变时，“位置稳定”或“零异常”不能验证那项主张。

核验方式若对错误产物也会通过，就查它与用户目标的关系。用当前可获得的具体反例修正这一处检查，不自动增加一整套测试。条件尽量相同；条件变化及作者辅助要保留，不能通过放宽真要求让新方案通过。

记录实际改变的决定或动作、产物位置、观察及未解问题即可。完整用户过程需要共同保留其他有效要求，例如屏幕变紧凑不能同时丢掉打印信息。结构变化、库调用、截图和录屏生成分别只证明相应事实；感知结论按 [实际体验取证](evidence-access.md#实际体验的取证) 检查。

## 对话与版本边界

只协调已获授权的接收方及任务。原对话仍在工作时先核对状态和新的人类指示，不为实验打断它。没有通信工具或协调许可时交付可带回原任务的材料，不假装已发送。

固定完整候选后再验证其采用，保留实际读取版本与输出位置即可，不搭建发布系统。原负责人执行任务、方法维护者修改 Skill，各自的结果分别说明。

压缩后改答旧任务时，先排除用户改题，再交回已有授权内的当前任务、入口和未完成产物；只补必要原文，不重发全部历史。记录此类人工提醒，不能把它计为 Skill 自主恢复。任务文件不会自行被宿主重新加载；隐藏上下文无法观察或控制时保留限制。

用户同时要求改进本包时，只把真实缺口放到对应工具或方法位置。领域制作由领域方法承担，规则已清楚时先查读取、解释、操作能力与检查是否有效。按 [效果验证](evaluation.md) 区分开发、原处采用与独立增益；不要因业务页面修好了就宣称 Skill 已普遍有效。
