# 容易混淆的判断

以下均为虚构教学例子，不是效果验证记录。借用判断方法，不照搬业务解法。

## 局部修好了，原目标却丢了

用户要一张可打印的工作清单，同时要求每项都显示负责人。后来反馈内容太挤。Agent 缩成一页，但把负责人改成点击后才能看到，并以“没有溢出”验收。

已经能确认的是：新产物满足一页显示，未满足打印时直接找到负责人。不能仅凭这个结果断定 Agent 忘记了上下文；它也可能读到了要求，却错误地把屏幕无溢出当成全部通过标准。

取证时连起三个位置：原来的打印用途和负责人要求、决定隐藏信息的理由、实际打印结果。修复比较应保持同一批内容和打印尺寸，同时检查页数、可读性与负责人是否仍可见。可以调整列宽、文字或页面组织，不预设唯一布局。

若用户后来明确说“只在电脑上用，可以点击查看负责人”，有效目标已经变化。此时保留旧的打印要求反而会理解偏。审查依据是当前仍有效的要求，不是永远保留所有历史要求。

## 审查者的比较条件变成了额外要求

用户要让新同事看懂并完成一套安装说明。审查者为比较两版，选了“一页、五步”的展示条件，随后把这两个数写成修复的通过标准。新版把前提塞进缩写，每步更短，检查全通过，但新人仍然装不起来。

用户要求的是能完成安装；一页、五步在这份材料中来自审查者。先查它们是否另有实际限制，例如纸质交付只有一个版面；没有依据就不能因为已写进检查而把它们当成硬约束。审查者自己也可能引入理解偏差，不能只检查原 Agent。

一项有区分力的检查是：保持真实输入和使用条件，让正常读者按说明找到所需前提、完成操作并识别成功；同时看原来的“一页五步”通过是否可能伴随这些失败。若有这种反例，修正标准及其适用范围，记录改动理由，再比较完整说明。不能只是放宽字数以让当前稿通过，也不能用新人后来得到作者现场帮助当作说明已独立奏效。

如果用户确实要求一页印刷，则一页仍是有效边界，需要在边界内重新组织，或就具体冲突提出取舍。这个例子不意味着尺寸、字数或位置检查都无效；关键是来源、适用条件，以及它们是否足以代表真实目标。

## 读过规则，仍不能证明方法有效

一个资料整理 Skill 要求引用原始来源。Agent 成功读取了入口，交付却只引用二手摘要。

先检查读取的版本与范围，再看实际判断：是否漏读必要参考？是否把转载误认成原始来源？是否找不到原文但没有说明？是否实际引用了原文而用户指的是另一项问题？这些解释对应不同修复。

如果正确取得原文、按方法操作后，成果仍不能满足任务，就要检查方法与通过标准本身。不能因为文档写有“必须核实”就把责任全归执行者；也不能因一次差结果证明所有版本都无效。

修复成果必须是可检查的来源和实际引用。新增“以后更认真”、朗读规则、成功安装工具、Agent 自称恢复，都不能替代它。

## 相对选择、允许实施与现在满意不同

用户先说“两个版本里第二个好些”，允许接入；实际使用后又说“仍然费力，前面的返工也没有解决问题”。

审查应保留两个事实：当时的实施获得许可，现在的效果仍被否定。不能改写历史为擅自实施，也不能用旧选择消除新反馈。先定位现在困难发生在哪个动作、状态或产物，再判断设计取舍或验收是否失准。

如果用户只要求查因，不联系其他对话。若随后明确授权协调原任务与方法维护者，按修复参考交接证据、固定待用版本、收回原任务真实结果。协调帮助必须计入验证条件；它不能证明 Skill 已经独立解决了同类问题。

如果两个案例共享方法、版本更新和协调者，它们可以相互提供线索，但不能当作两个独立实验。公开包只保留上述通用判断；真实原文、私有路径和截图留在获准的案例材料中。
